Product Specification · Internal / Engineering

Virtual Knowledge Graph (VKG) Layer

tabularis 위에 얹는 SPARQL 기반 시맨틱 조회 레이어 — 원본 관계형 데이터는 건드리지 않는 순수 가상 계층.

Doc v1.0 2026-08-24 Audience: 내부 개발팀 Stack: Tauri 2 · Rust · React 19 Repo: kncsolution/vkg (fork of TabularisDB/tabularis)

01 개요

VKG는 사용자의 관계형 DB(RDB) 위에 Ontology(온톨로지) · Mapping(R2RML/OBDA) 계층을 얹어, 원본 스키마를 수정하지 않고도 SPARQL로 질의 가능한 지식 그래프 뷰를 제공하는 tabularis의 신규 레이어입니다. 질의는 Ontop 엔진이 SPARQL → SQL로 실시간 재작성(rewriting)해 실행하며, 결과는 항상 RDB의 현재 상태를 그대로 반영합니다 — 별도 그래프 DB로의 ETL/복제가 없습니다.

RDB (read-only)→ Ontology (OWL/Turtle)→ Mapping (.obda)→ Pipeline→ Rule→ Ontop→ SPARQL Endpoint
핵심 설계 원칙: 비파괴적(non-destructive). VKG의 모든 계층은 RDB에 대한 읽기 전용 뷰이며, Ontop 컨테이너는 프로젝트 단위로 격리되어 기동됩니다.

02 아키텍처 스테이지

각 VKG 프로젝트는 5개 계층을 순서대로 통과해 SPARQL 엔드포인트가 됩니다.

Stage 1
Ontology

OWL 클래스/속성 정의 (Turtle 직렬화). Mapping Bootstrap으로 스키마에서 자동 생성하거나 Ontology Editor에서 수동 편집.

Stage 2
Mapping

R2RML 스타일 .obda 매핑 — 테이블 행을 RDF 리소스/트리플로 변환하는 규칙. Class Mapping / Relationship Mapping 두 종류.

Stage 3
Pipeline

여러 클래스를 조인·집계·UNION·체이닝해 하나의 재사용 가능한 데이터 소스로 결합. Rule이 실행되는 대상.

Stage 4
Rule

AND/OR 조건 체인을 SPARQL FILTER/HAVING으로 컴파일하는 결정론적 검증 규칙. 검증/기간비교/What-if 3종 실행 모드 공유.

Stage 5
Ontop Runtime

프로젝트별 Docker 사이드카로 기동되는 SPARQL-to-SQL 재작성 엔진. 저장된 Ontology/Mapping을 로드해 라이브 엔드포인트를 노출.

UI
SPARQL Editor

임의 SPARQL 실행 + 결과의 테이블/그래프 토글 뷰. 그래프 뷰는 클래스/인스턴스 노드 구분과 N-hop 자동 확장을 지원.

03 Pipeline 데이터 모델

Pipeline은 단일 클래스부터 다중 조인·집계·UNION·체이닝까지 하나의 타입으로 표현됩니다 (조인 0개 = 순수 단일 클래스 Rule과 완전히 동일).

필드역할
base_class / joins[]기준 클래스 + 임의 깊이 조인 체인 (A→B→C…). 각 hop은 from_alias로 이전 hop 또는 base에서 이어붙임.
aggregateGROUP BY + SUM/COUNT/AVG/MIN/MAX 집계. 설정 시 Rule 조건은 FILTER 대신 HAVING으로 컴파일.
union_of서로 다른 조인 체인 여러 개를 SPARQL UNION으로 통합 (arm별 필드를 통일된 이름으로 매핑).
source_pipeline_id다른 Pipeline의 출력(집계 결과 포함)을 그대로 입력으로 체이닝 — 서브쿼리로 임베드.
compute[]체이닝된 Pipeline 위에서 계산되는 파생 필드. branches(WHEN AND/OR 조건 → 값) + default_value(ELSE), 값은 리터럴 / 원본 필드 / 산술식(+ − × ÷) 중 하나. 중첩 IF(...)로 컴파일.

04 Rule 데이터 모델

필드역할
conditions[]속성/연산자/값 + AND·OR logical_operator로 체이닝되는 조건 행 목록. 연산자 10종 (같음/다름/대소/차이/포함/비어있음 등).
period날짜 범위 바인딩 — 조건과 별도로 관리되어 기간 드롭다운으로만 조정.
RuleExecutionOverrides저장된 Rule을 변경하지 않고 이번 실행에만 기간/조건값을 덮어씀 — 기간 비교와 추론(What-if)이 이 메커니즘 하나로 구현됨.
RuleExecutionResult실행 스냅샷(전체/위반 건수 + 위반 행)을 그대로 영속화 — 감사 추적을 위해 재계산하지 않고 그 시점 판정을 보존.

05 VKG 생성 마법사 (6단계)

CreateVkgWizard — 기존 tabularis 연결을 그대로 재사용해 처음부터 끝까지 클릭만으로 VKG 프로젝트를 만드는 온보딩 플로우.

1Select Data Source

저장된 연결(connection) 중 하나 선택.

2Select Schema

자동 생성 대상 테이블 체크박스 선택.

3Bootstrap Mapping

선택 테이블에서 Ontology + Mapping 자동 생성 실행.

4Create Ontology

생성된 Class/Property 목록 확인.

5Review

이름·소스·테이블·클래스 수 최종 확인.

6Start VKG

프로젝트 확정 (Ontop 기동 연결은 후속 작업).

06 기능 범위 & 알려진 한계

기능상태비고
Mapping Bootstrap범위 제한단일 컬럼 PK 테이블만 지원. 복합키/자기참조/N:M 조인테이블은 Mapping Editor에서 수동 매핑 필요.
Pipeline 조인/집계/UNION/체이닝완료임의 깊이 조인, GROUP BY 집계, 다중 arm UNION, Pipeline 체이닝 모두 지원.
Compute 필드 (다중분기/산술/AND·OR)완료CASE WHEN 다중 branch, 조건 AND/OR 체이닝(Rule과 동일 모델 재사용), 산술 연산(+ − × ÷) 지원.
Rule 검증/기간비교/What-if완료세 실행 모드가 동일 to_sparql 경로 + overrides 인자 하나로 구현.
SPARQL 결과 그래프 뷰완료클래스/인스턴스 노드 구분, 드래그 이동, N-hop 자동 확장(BFS, hop당 최대 200 프론티어).
Ontop 실기동 연결 (§13)예정마법사 6단계 "Start VKG"는 현재 상태 마킹만 수행. Docker 사이드카 실제 기동은 별도 작업.
Rule 실행 이력 UI / 대시보드예정스냅샷은 저장되지만 조회 UI·스케줄링·시각화 대시보드는 백로그.
